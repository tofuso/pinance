# データ削除機能 設計ドキュメント

**作成日:** 2026-03-20
**対象機能:** 読み込んだCSVデータの削除

---

## 概要

銀行取引データおよびカード取引データを、全件または月単位で削除できる機能を追加する。
操作は設定モーダルを通じて行う。

---

## 要件

- 銀行取引データ・カード取引データをそれぞれ独立して削除できる
- 削除の粒度は「全件削除」と「月単位削除」の2種類
- 操作はヘッダーの設定ボタンから開くモーダル経由で行う
- **全件削除のみ** `confirm()` ダイアログで確認を取る（月単位削除は確認なし）
- 削除成功後はトースト通知＋画面データの再読み込みを行う

---

## バックエンド設計

### 新規APIエンドポイント

#### 銀行取引

| メソッド | パス | クエリパラメータ | 機能 |
|---|---|---|---|
| `GET` | `/api/bank/months` | なし | DB上の銀行取引の月一覧（`YYYY-MM`形式、昇順）を返す |
| `DELETE` | `/api/bank/transactions` | なし | 銀行取引を全件削除 |
| `DELETE` | `/api/bank/transactions` | `year_month=YYYY-MM` | 指定月の銀行取引を削除 |

#### カード取引

| メソッド | パス | クエリパラメータ | 機能 |
|---|---|---|---|
| `GET` | `/api/card/months` | なし | DB上のカード取引の月一覧（`YYYY-MM`形式、昇順）を返す |
| `DELETE` | `/api/card/transactions` | なし | カード取引を全件削除 |
| `DELETE` | `/api/card/transactions` | `year_month=YYYY-MM` | 指定月のカード取引を削除 |

> **実装注意:** `DELETE /api/bank/transactions` は `year_month` パラメータの有無で全件削除か月指定削除かが変わる。
> パラメータ受け取り漏れによる意図しない全件削除を防ぐため、バックエンド実装では `year_month` の受け取りを明示的に検証すること。

### レスポンスモデル

`models.py` に以下を追加：

```python
class DeleteResponse(BaseModel):
    deleted: int  # 削除した件数
```

月一覧のレスポンスは `list[str]`（例: `["2024-06", "2024-07", "2024-08"]`）。

### 変更ファイル

- `src/pinance/models.py` — `DeleteResponse` モデル追加
- `src/pinance/routers/bank.py` — months GETエンドポイント・DELETEエンドポイント追加
- `src/pinance/routers/card.py` — 同上

## フロントエンド設計

### ヘッダー変更

既存のインポートボタン群の右に「⚙」ボタンを追加する。

### 設定モーダル

```
┌──────────────────────────────┐
│ データ管理                ✕  │
├──────────────────────────────┤
│ 銀行取引                     │
│  [2024年8月 ▼] [選択月を削除] │  ← データなし時は無効化
│  [全件削除（赤）]             │  ← confirm()あり
├──────────────────────────────┤
│ カード取引                   │
│  [2024年8月 ▼] [選択月を削除] │  ← データなし時は無効化
│  [全件削除（赤）]             │  ← confirm()あり
└──────────────────────────────┘
```

### 動作フロー

1. ⚙ボタンクリック → モーダルを開く
2. モーダルオープン時に `/api/bank/months` と `/api/card/months` を並列呼び出し
   - 月一覧が空の場合、ドロップダウンと「選択月を削除」ボタンを無効化（`disabled`）する
   - 月一覧が存在する場合、`YYYY-MM`形式を「YYYY年M月」に変換して表示する
3. 「選択月を削除」クリック → `DELETE /api/bank/transactions?year_month=YYYY-MM` を呼び出し
4. 「全件削除」クリック → `confirm("銀行取引データを全件削除しますか？")` → OKの場合のみ `DELETE /api/bank/transactions` を呼び出し
5. 削除成功後 → トースト表示 → 現在表示中の画面データを再読み込み → 月一覧を再取得してドロップダウン更新

### エラーハンドリング

- `deleted: 0` が返された場合、トーストに「削除するデータがありません」と表示
- API呼び出し失敗時はトーストにエラーメッセージを表示
- `confirm()` でキャンセルした場合は何も行わない

### 変更ファイル

- `src/pinance/static/index.html` — 設定ボタン・モーダルHTML追加
- `src/pinance/static/app.js` — モーダル開閉・削除API呼び出しロジック追加
- `src/pinance/static/style.css` — モーダルスタイル追加（既存ファイルへの追記）

## テスト観点

### バックエンド

- 全件削除後にDBが空になること
- 月指定削除で指定月のデータのみ削除され、他月は残ること
- 月一覧APIが削除後に更新された一覧を返すこと
- データが0件の状態で削除しても `deleted: 0` でエラーにならないこと

### フロントエンド

- `confirm()` でキャンセルした場合に削除APIが呼ばれないこと
- API失敗時にトーストがエラーメッセージを表示すること
- 削除後にドロップダウンが更新されること（月一覧の再取得）
- データ0件時にトーストが「削除するデータがありません」と表示されること
- データが存在しない状態でモーダルを開いたとき、月選択と削除ボタンが無効化されること
